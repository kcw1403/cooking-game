# 개발 기록

유아(만 3세 전후)용 아이패드 놀이 웹앱을 만들면서 진행한 내용, 받은 피드백, QA 결과, 남은 할 일을 정리한 문서입니다.
개발은 Claude Code(AI 코딩 도구)와 대화하면서 진행했습니다. 커밋 단위의 변경 내용은 `git log`에서도 볼 수 있습니다.

## 1. 목표와 원칙

- 아이가 앉아서 집중해서 할 수 있는 **절차형 놀이**를 만듭니다. 예를 들어 샌드위치는 채소 씻기 → 자르기 → 계란 삶기 → 깨기 → 으깨기 → 바르기 → 쌓기 → 먹기 순서로 진행합니다.
- 아이패드에서 손가락으로 조작하고, 가로·세로 화면 모두에 맞춥니다.
- 글을 못 읽는 나이라 모든 안내를 음성으로 읽어 주고, 아이가 머뭇거리면 손가락 힌트로 누를 곳을 보여 줍니다.
- 틀려도 혼내지 않고 다시 해 볼 수 있게 합니다. 실수로 놀이에서 나가지 않도록 막습니다.
- 설치 없이 열리도록 HTML 파일 하나씩으로 만들고, 외부 이미지나 소리 파일을 쓰지 않습니다.

### 3.2 숫자 놀이터 QA

| 문제 | 반영 |
|---|---|
| (버그) "더 적을까요?" 문제를 맞혀도 "많아요"라고 읽음 | 적다 문제에서는 "○ 개가 ○ 개보다 적어요"로 읽음 |
| 아이가 가만히 있으면 아무 반응이 없음 | 8초 뒤 문제를 다시 읽고 누를 곳을 반짝임, 그 뒤 12초마다 반복 |
| 9개와 10개처럼 1개 차이는 눈으로 비교하기 어려움. 두 접시의 줄 수가 달라 헷갈림 | 차이를 2개 이상으로 하고, 두 접시의 한 줄 개수를 같게 맞춤 |
| 처음부터 1~10은 어려움 | 처음 범위를 1~5로 하고, 바꾸면 기억 |

| 세는 그림에 ⭐가 나오면 칭찬 별과 헷갈림 | 세는 그림에서 ⭐를 빼고 🍊로 바꿈 |
| 많다 적다에서 접시 그림을 세어 볼 방법이 없음 | 접시마다 "🔢 세어 볼까?" 버튼 추가. 누르면 그림을 0.7초마다 하나씩 노랗게 표시하며 "하나, 둘…"을 읽고, 끝나면 "○ 개!"를 읽고 버튼에 "🔢 ○개"를 표시함. 별은 주지 않음. 다른 접시를 세거나, 접시를 누르거나, 다음 문제로 넘어가면 세던 것을 멈춤. 8초 동안 반응이 없으면 두 버튼을 반짝임 |

| 배포 | GitHub Actions의 Pages 배포 결과와 배포된 파일 내용 확인 | 통과 |
| 실제 아이패드 터치·소리 | 직접 플레이 | 사용자가 확인함. 음성이 기계음 같다는 피드백 |

참고: 미리보기 창이 가려진 상태에서는 애니메이션이 진행되지 않아, 자동 테스트 때는 애니메이션을 끄고 실행했습니다.

## 5. 음성 교체 검토 (진행 중)

기기 기본 음성(Web Speech API)은 설정을 바꿔도 기계 느낌이 남아서, 문장을 미리 mp3로 만들어 넣는 방식을 검토하고 있습니다.
게임은 mp3가 있으면 그것을 틀고, 없으면 지금처럼 기본 음성으로 읽도록 바꿀 계획입니다.

| 후보 | 특징 | 비고 |
|---|---|---|
| Microsoft Azure Speech | 공식 클라우드 TTS, 무료 한도 월 50만 자 | 가입·결제 수단 필요 |
| Google Cloud TTS | 공식 클라우드 TTS, Chirp 3 HD 음성 | 가입·결제 수단 필요 |
| 네이버 CLOVA Voice | 한국어 특화 | 유료, 약관 확인 필요 |
| Voicebox (로컬 오픈소스) | 무료, PC에서 실행, 목소리 복제 가능, 로컬 REST API | 설치 용량 큼, 한국어 품질과 모델별 라이선스 확인 필요 |
| 직접 녹음 | 가장 자연스러움 | 문장 수가 많아 시간이 걸림 |

참고: 한국어 TTS 서비스별 점유율은 공개된 신뢰할 만한 자료를 찾지 못했습니다. 그래서 같은 문장을 직접 들어 보고 비교하기로 했습니다.

### 5.1 1단계: 재생 코드와 문장표 (2026-11-14)

| 항목 | 내용 |
|---|---|
| 재생 방식 | 네 화면의 `speak()`가 `VOICE.play()`를 거칩니다. `voice/list.js`의 `VOICE_FILES`에 있는 문장은 `voice/<문장 해시>.mp3`를 Web Audio로 재생하고, 없거나 파일을 못 받으면 기기 음성으로 읽습니다. 지금은 목록이 비어 있어 예전과 똑같이 기기 음성으로 읽습니다 |
| 이어 읽기 | "사과! 잘했어요!"처럼 낱말·숫자·칭찬을 이어 붙이던 문장은 배열로 나눠 조각 mp3를 차례로 재생합니다. 조합마다 mp3를 만들지 않아도 됩니다. 한 조각이라도 mp3가 없으면 전체를 기기 음성으로 읽습니다 |
| 문장 바꿈 | 이어 읽기 때문에 일부 문장이 조금 바뀌었습니다. "일, 잘했어요!" → "일! 잘했어요!", "사과, 잘했어요!" → "사과! 잘했어요!" |
| 아이패드 | 첫 터치 때 소리 장치(AudioContext)를 켜 두어, 그 뒤 타이머로 읽는 문장도 mp3로 재생됩니다 |
| 문장표 | 각 화면의 `voiceLines()`를 `tools/voice-lines.html`이 모아 `docs/음성문장.txt`를 만듭니다. 문장 1103개, 글자 6304자 (선택 화면 3, 요리 73, 한글 892, 숫자 144) |
| 넣지 않은 문장 | 글자 만들기(마음대로)에서 받침 있는 글자는 만 개가 넘어서 넣지 않았습니다. 이 글자는 계속 기기 음성으로 읽습니다. 받침 없는 글자 399개는 넣었습니다 |

2단계에서 확인할 점:
- "ㄸ은 받침이 될 수 없어요"처럼 자모 기호가 들어간 문장 3개는 TTS 서비스가 기호를 제대로 읽는지 확인합니다. 제대로 못 읽으면 mp3를 만들 때만 "쌍디귿은"으로 바꿔 읽힙니다.
- 받침 없는 글자 중 "꺠, 떄"처럼 잘 안 쓰는 글자도 TTS 서비스가 제대로 읽는지 확인합니다.

### 5.2 2단계: Azure 음성으로 mp3 만들기 (2026-11-14)

| 항목 | 내용 |
|---|---|
| 서비스 | Microsoft Azure Speech, 무료 계층(F0, 매월 50만 자), 지역 Korea Central |
| 음성 고르기 | 여성 5개(선히, 지민, 서현, 순복, 유진)와 남성 1개(인준)를 기본·90% 빠르기로 같은 문장 5개씩 만들어 비교함 → 선히(ko-KR-SunHiNeural), 기본 빠르기로 정함. "ㄸ은", 이어 붙인 조각 간격도 괜찮음 |
| 만들기 | `tools/make-voice.ps1`이 `docs/음성문장.txt`의 문장마다 `voice/<mp3 이름>.mp3`를 만들고 `voice/list.js`를 다시 씀. 무료 계층은 1분에 20건까지라 요청 사이를 3.1초 띄움 (1103문장에 약 1시간). 이미 있는 mp3는 건너뜀 |
| 키 | 사용자 환경 변수 `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION`에만 둠. 저장소에 넣지 않음 |
| 결과 | 1103문장 모두 mp3로 만듦 (실패 0, 합계 약 14MB, 약 1시간 2분). `voice/list.js`에 1103개 등록 |
| 문장을 바꿨을 때 | `tools/voice-lines.html`로 `docs/음성문장.txt`를 다시 만들고 `tools/make-voice.ps1`을 실행하면 새 문장만 만듦. 쓰지 않게 된 mp3는 남으므로 가끔 정리함 |
