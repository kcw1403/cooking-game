# 3D 그림체 SVG 규칙

요리 놀이의 재료·도구 이모지는 Microsoft Fluent Emoji 3D 그림(`img/fluent/`)으로 보인다.
직접 그리는 그림(SVG, CSS 도형, canvas)은 이 그림들 옆에 놓여도 어색하지 않게 아래 규칙을 따른다.
지금까지 이 규칙으로 그린 예: `cooking.html`의 `GRAPE_SVG`(포도 한 알), `APPLE_SVG`(사과 조각), `PADDLE_SVG`(밥 주걱), 김밥 밥 펴기 장면(`riceClump`), 공용 그릇(`.bowl`)·접시(`.plate`)·도마(`.board`), 밥솥(`.ricepot`), 주먹밥(`.riceball`), 무대 배경(`#stage`, 밝은 대리석 조리대).

## 0. 공용 바탕

- 무대 배경은 밝은 대리석 조리대다. 나무 도구(도마, 김발, 꼬치)가 묻히지 않게 배경을 나무색으로 바꾸지 않는다.
- 밥은 반복 무늬 대신 한 장짜리 밥 그림 `var(--ricetex)`(`makeRiceTexture`, 640×640)를 `center/cover`로 쓰고, 그 위에 왼쪽 위 반사·오른쪽 아래 그늘 그라데이션을 겹친다.

## 1. 빛과 입체감

1. 빛은 항상 **왼쪽 위**에서 온다.
2. 면은 단색으로 칠하지 않고 **3단 그라데이션**(밝은 색 → 본색 → 어두운 색)으로 칠한다.
   - 둥근 물체: `radialGradient`, 중심을 왼쪽 위로 치우침 (`cx="35~40%" cy="30~35%" r="65~75%"`)
   - 납작하거나 긴 물체(도마, 김발 살, 손잡이): `linearGradient`, 위·왼쪽이 밝게
3. **반사광**: 왼쪽 위에 하얀 타원 하나 (`fill="#fff" opacity=".45~.6"`), 물체 크기의 15~25%. 반짝이는 재질(과일, 그릇, 금속)일수록 진하게, 천·밥·빵처럼 거친 재질은 `.2~.3`으로 옅게.
4. **바닥 그림자**: 물체 아래에 옅은 타원 (`fill="rgba(0,0,0,.15)"`). 물체 너비의 60~70%, 높이는 너비의 1/6 정도.
5. 테두리 선은 쓰지 않는 것이 기본이다. 경계가 흐려지면 본색보다 한 단계 어두운 같은 계열 색으로 1~2px만 쓴다. 검은 테두리는 쓰지 않는다.

## 2. 모양과 색

1. 모서리는 모두 둥글게 한다. 각진 사각형 대신 `rx`가 있는 사각형, 직선 대신 살짝 휜 곡선(`Q`, `C`)을 쓴다.
2. 비율은 실제보다 조금 통통하고 귀엽게 (아이용 그림).
3. 색은 채도가 높고 밝게. 회색·갈색도 따뜻한 쪽으로 (예: 회색 냄비 `#d9dee3 → #9aa3ab → #5f6870`).
4. 자주 쓰는 색 (밝은 색 / 본색 / 어두운 색):
   | 대상 | 색 |
   |---|---|
   | 빨강(토마토, 사과 껍질) | `#ff6b6b` / `#e3262f` / `#a5121c` |
   | 보라(포도) | `#c79bf2` / `#8a4fd0` / `#4a1f86` |
   | 노랑(달걀노른자, 단무지) | `#fff3a0` / `#ffd400` / `#e0a800` |
   | 초록(김) | `#3f6b4c` / `#1f3a2a` / `#0e1f15` |
   | 밥·속살 | `#ffffff` / `#fbf6ea` / `#e8dcc0` |
   | 나무(도마, 김발, 주걱) | `#f6e3b4` / `#e2c27e` / `#b88a46` |

## 3. SVG 작성 방법

1. `viewBox="0 0 100 100"`을 기본으로 하고, `style="width:100%;height:100%;display:block;overflow:visible"`로 감싸는 요소 크기에 맞춘다. 크기는 감싸는 요소에서 `uu(n)`(=`calc(var(--u)*n)`)으로 정한다.
2. 그라데이션 `id`는 그림마다 고유한 접두어를 붙인다 (예: `grpg`, `apsk`). 같은 그림을 여러 번 넣는 것은 괜찮다 (같은 정의라서).
3. 그림은 상수 문자열(`XXX_SVG`)로 두고, 만드는 함수(`grapeBall(parent,size)`처럼)를 함께 둔다.
4. 이미지 파일을 새로 만들지 않는다. 외부 라이브러리를 쓰지 않는다.
5. 터치를 받는 요소는 그림을 감싼 `div`다. 그림 안의 작은 조각이 터치를 가로채지 않게 필요하면 `pointer-events:none`을 준다.

## 4. canvas로 칠하는 장면 (바르기, 펴기)

1. 칠하는 한 번(dab)을 단색 원으로 찍지 않는다. **가장자리가 부드러운 덩어리**(가운데 밝고 가장자리로 갈수록 투명한 `createRadialGradient`)를 찍고, 그 위에 재질 조각(밥알, 소스 반점)을 얹는다.
2. 재질 조각도 입체감 규칙을 따른다: 조각마다 아래쪽에 옅은 그림자, 위쪽에 작은 반사광.
3. 덩어리 그라데이션은 반지름의 70~85%까지 꽉 차게 칠하고 바깥 15%만 짧게 사라지게 한다. 처음부터 흐리게 빠지면 가장자리가 번져 보인다.
4. 덩어리 중심은 칠하는 영역 가장자리에서 반지름의 절반 정도 안쪽으로만 찍는다(`riceClumpIn`). 그래야 가장자리가 반듯하게 잘리지 않고 몽글몽글하다.
5. 다 칠하면(완료) 덜 칠한 빈틈을 짧은 애니메이션으로 마저 채우고, 그 canvas를 `toDataURL`로 저장해 다음 단계에서 같은 그림을 쓴다(예: `S.riceImg`). 다른 무늬로 바꾸면 느낌이 달라진다.
6. 얇은 층(밥, 소스)은 `filter:drop-shadow`로 아래에 짧은 그림자를 떨어뜨려 두께를 낸다.
7. 빽빽하게 겹치는 재질 조각(큰 밥 그림의 밥알)은 그림자·테두리를 옅게(`soft`) 해야 전체가 칙칙해지지 않는다.

## 5. 색칠 그림 (coloring.html) — 테두리 예외

색칠 그림은 칸을 구분해야 하므로 1-5번의 "테두리 선을 쓰지 않는다" 규칙의 예외다.

1. 그림판은 `400×300`. 칸(`regions`)은 SVG path 문자열로, **뒤에 있는 칸부터 앞에 있는 칸 순서**로 적는다. 앞 칸이 뒤 칸과 뒤 칸의 선을 가린다.
2. 선은 진갈색 `#4a3426`, 칸 테두리 4.2, 눈·입 같은 `details` 선 3.4 (그림판 단위), 둥근 끝·둥근 이음.
3. 눈은 `EYE(x, y, r)`: 진갈색 점 + 왼쪽 위 하얀 반사점. 칠하는 칸이 아니라 `details`에 넣는다.
4. 칸 수는 6~11개. 아기 손가락으로 누를 수 있게 가장 작은 칸도 대략 18×18 단위 이상으로 한다 (작은 코·꼭지는 조금 크게 그린다).
5. 칠한 칸의 빛·그늘은 엔진이 자동으로 넣는다(`drawShade`: 왼쪽 위 밝게, 오른쪽 아래 그늘). 그림에 따로 넣지 않는다.
6. 새 그림을 넣으면 모든 칸에 보이는 점이 있는지(앞 칸에 완전히 가려진 칸이 없는지) 자동으로 확인하고, 그림 고르기 화면과 다 칠한 모습을 캡처해 본다. 보이는 넓이가 그림판 단위 150(약 12×12) 아래인 칸은 키운다.
7. 그림마다 `cat`에 카테고리 id(`CATS`)를 적는다. 카테고리마다 8장을 맞추면 그림 고르기 화면이 4×2로 스크롤 없이 보인다.
8. 도우미: `RR`(둥근 네모), `MX`(좌우 뒤집기), `TX`(옮기기), `STAR`, `PETAL`(꽃잎·날개), `HEART`, `SPARK`(반짝이), `DROP`(빗방울), `CLOUD`, `SCALLOP`(물결 동그라미), `GROUND`(땅). `MX`·`TX`는 절대 좌표 `x y` 쌍만 있는 경로에 쓰고, `E()` 타원에는 쓰지 않는다. 가운데가 빈 칸(도넛, 고리)은 `E(...) + ER(...)`로 만든다.

## 6. 확인 방법

1. 로컬 서버를 띄우고, 새 그림이 Fluent 3D 그림과 **같은 화면에 함께 나오는 단계**에서 가로 1024×768, 세로 768×1024로 캡처해 나란히 비교한다. 빛 방향, 그림자, 채도가 맞는지 본다.
2. 같은 그림을 작게(꼬치, 쟁반) 쓸 때와 크게 쓸 때 모두 확인한다. 작게 보일 때 반사광이 너무 크거나 세부가 뭉개지지 않는지 본다.
3. 요리 놀이를 고쳤으면 `CLAUDE.md`의 테스트 절차대로 7종 자동 플레이를 통과시킨다.
4. 바꾼 그림과 이유를 `docs/개발기록.md` 3.6절 표에 한 줄 추가한다.
